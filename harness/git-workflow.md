# Git 작업 규칙

## 제목과 본문

- 커밋 제목과 PR 제목은 `feat:`, `fix:`, `refactor:`, `docs:` 등 변경 유형 접두사 뒤에 한국어로 작성합니다. `Overview`처럼 화면에 표시되는 이름과 기술 용어는 원래 표기를 사용할 수 있습니다.
- 커밋이나 PR에 설명이 필요하면 변경한 동작과 검증 결과를 한국어로 작성합니다.

| 항목      | 예시                                                       |
| --------- | ---------------------------------------------------------- |
| 커밋 제목 | `feat: 실험 목록에 무한 스크롤 추가`                       |
| PR 제목   | `feat: 실험 비교 대시보드 및 Overview 상위 실험 순위 추가` |

## 실행 전 확인

- 커밋을 목적별로 나누고, 만들기 전에 각 제목과 포함할 변경을 확인합니다.
- 사용자가 커밋 전 확인을 요청하면 커밋 목록과 각 커밋의 범위를 먼저 공유하고 승인 후 진행합니다. PR 생성은 사용자가 요청한 범위에 따릅니다.
- 스테이징 전에 변경 파일을 확인하고, 커밋 직전에 `git diff --cached --name-status`로 포함 파일을 다시 확인합니다. 로컬 작업 메모, 자동 생성 산출물, 비공개 연구 데이터, 학교 서버와 GPU 환경 정보, 비밀값은 커밋과 PR에서 제외합니다.
- 커밋 전 [프론트엔드 검증 기준](frontend-workflow.md#검증)에 따라 필요한 검사를 완료합니다.
- PR을 열기 전에 대상 브랜치가 `develop`인지, 이번 작업의 커밋만 포함되는지 확인합니다.
- 이번 작업이 선행 PR에 의존하면 선행 PR이 `develop`에 머지됐는지 확인한 뒤, 최신 원격 `develop` 기준으로 커밋 범위를 다시 확인합니다.
- PR을 열거나 제목을 수정한 뒤 GitHub에 표시되는 PR 제목과 커밋 제목을 확인합니다.
