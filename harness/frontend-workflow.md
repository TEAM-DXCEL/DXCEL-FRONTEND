# 프론트엔드 구현과 검증 규칙

## 구현

- 의존성 설치와 스크립트 실행에는 `pnpm`을 사용합니다. 의존성이 바뀌면 `pnpm-lock.yaml`도 함께 갱신합니다.
- UI를 수정할 때는 [공통 UI 컴포넌트](../docs/ui-components.md)와 [디자인 토큰](../docs/design-tokens.md)을 먼저 확인합니다. 색상, 타이포, 간격, 테두리는 기존 토큰을 사용합니다.
- 대시보드는 데스크톱을 기준으로 설계합니다. 좁은 창에서도 표 영역을 가로로 스크롤할 수 있게 하고, 추가 로딩이 표의 가로 위치에 영향을 받지 않도록 확인합니다.
- Next.js 정적 내보내기 구조를 따릅니다. 비공개 연구 데이터와 관리자 키, 수집 토큰은 클라이언트 코드나 정적 빌드에 포함하지 않습니다.

## 실험 지표

- 평가 방향과 목표값은 지표별로 적용합니다. 차트, 표, Baseline 비교에서 같은 기준을 사용합니다.
- 값이 없으면 미측정으로 표시하고 차트의 해당 점과 비교 계산에서 제외합니다. 실제 측정값 `0`은 유효한 값으로 처리합니다.
- 샘플 결과는 화면에서 샘플임을 표시합니다. 지표 선택과 비교 동작은 [실험 문서](../docs/experiments.md)를 참고합니다.

## 검증

- 커밋 전 `pnpm check`를 실행합니다. 화면, 정적 경로, 빌드 설정을 바꿨다면 `pnpm build`도 실행합니다.
- UI 버그를 수정했다면 문제가 발생한 화면 폭과 조작 순서로 다시 확인합니다.
- 단순 UI, 스타일, props 전달이나 구현을 그대로 반복하는 로직의 테스트는 추가하지 않습니다.
