# 실험 목록과 도메인 타입

현재 `/experiments`는 실제 연구 기록과 분리된 가상 데이터 12개를 사용한다. 화면에 샘플 데이터임을 명시한다. DB·인증·수집 API는 연결하지 않았으며 실제 지표 값도 넣지 않는다.

## 타입과 DB 설계의 관계

`src/features/experiments/types.ts`는 백엔드 `docs/database-design.md`의 논리 설계에 맞춘 프론트 도메인 타입이다. DB에서 생성한 타입이나 확정된 API 응답 규약은 아니다. migration 구현 후 생성되는 DB 타입과 조회 adapter를 통해 연결한다.

| 타입 | 역할 |
| --- | --- |
| `Experiment` | 프로젝트 안의 고정 실험 번호, 담당자, 이전 실험, 현재 설계·대표 결과 참조 |
| `ExperimentRevision` | 가설·변경 내용·변경 이유·평가 계획의 버전 |
| `RunGroup` | 같은 비교 조건의 반복 묶음과 확정 상태 |
| `Run` | 개별 실행, 반복·재시도 번호, 이전 평가 참조와 상태 |
| `RunMetric` | 지표 정의 참조와 측정·결측·오류의 구분 |
| `ExperimentListItem` | 현재 설계와 최신 실행을 조합한 목록용 조회 모델 |

실행 성공은 실험의 개선이나 최종 확정을 의미하지 않는다. 최신 실행 상태와 대표 결과를 분리한다. 결과 정정·재평가는 이전 실행을 덮어쓰지 않고 새 실행으로 연결한다. 결측·오류 값을 0으로 표시하지 않는다.

상태 이름과 필드 이름은 이번 화면 구현의 초안이다. 프로젝트 간 참조·유한 수치·확정 후 불변성 등의 강제는 향후 DB·API에서 수행해야 하며 TypeScript 타입이 이를 보장하지 않는다. 샘플 ID는 가독성을 위한 문자열이며 실제 저장 식별자는 기존 설계의 UUID를 따른다.

## 화면 동작

- 번호·제목·담당자·변경 내용·변경 이유 검색: 검색 버튼 또는 Enter로 적용
- 최신 실행 상태: 실행 전·대기·실행 중·성공·실패·취소
- 최근 업데이트순 또는 실험 번호 오름차순·내림차순 정렬
- 페이지당 8개 표시, 변경 이유·가설·평가 계획 펼치기
- 로딩, 빈 목록, 검색 결과 없음, 조회 오류와 다시 시도 표시
- `q`, `status`, `sort`, `page` URL 파라미터로 조건 유지; 브라우저 뒤로·앞으로 이동 지원

잘못된 상태·정렬·페이지 파라미터는 기본값으로 처리한다. 범위를 넘는 페이지는 마지막 페이지로 제한하며 필터를 바꾸면 첫 페이지로 이동한다. 날짜는 KST로 표시한다.

조회는 `repository.ts`의 `listExperiments(query, signal)`로 분리했다. 현재 샘플 전체를 메모리에서 검색·정렬한 후 자른다. 이는 실제 DB의 pagination 구현이 아니다. DB 연결 시 인증된 프로젝트 범위 조회와 cursor pagination을 구현하고 페이지 UI도 해당 응답 계약에 맞춘다. 실제 비공개 데이터를 정적 빌드에 포함하면 안 된다.

이번 범위에 실험 생성·편집, 상세 경로, 비교 대상 선택·비교, Baseline 선정은 포함하지 않는다. 실제 지표 표시는 지표 정의와 확정 실행 묶음 계약을 구현한 뒤 연결한다.
